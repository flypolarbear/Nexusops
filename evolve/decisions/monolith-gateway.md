# 单体网关架构决策

## 状态

已采纳

## 背景

NexusOps 当前后端以 FastAPI 为主。产品在首期没有硬上线时间约束，但要求尽快形成稳定的 Agent 通用接入逻辑，并兼容现有 Jenkins/ArgoCD 等系统。

## 决策

采用 **FastAPI 单体内核 + 可插拔执行层**：

1. Gateway 控制面（路由、鉴权、限流、审计、统一错误）落在现有 FastAPI 内
2. Agent 执行面采用可插拔 Adapter/Executor 模型
3. 预留独立部署边界

## 理由

1. 最快形成可交付能力，降低初期研发成本
2. 避免"先微服务后产品"的过度设计
3. 通过可插拔执行层提前消除后续重构成本

## 触发拆分的条件

- 吞吐量 > 10,000 QPS
- 需要独立扩展
- 需要物理租户隔离

## 影响

- **开发**: 短期效率高，模块边界需严格定义
- **测试**: 重点覆盖合约一致性与插件兼容性
- **运维**: 先沿用现有发布链路，后续可平滑迁移

## 约束

- 不在 Handler 中直接写第三方调用逻辑，必须通过 Executor 接口
- 所有 Agent 调用必须经过统一中间件链
- 为未来拆分保留明确模块目录与内部 API 边界
