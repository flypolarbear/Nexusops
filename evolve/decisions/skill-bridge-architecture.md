# Skill Bridge 架构决策

## 状态

已采纳 (2026-03-02)

## 背景

当前 NexusOps 架构中：
1. Skills 从 skills.sh 同步到数据库，但只作为静态内容存储
2. Agent 执行依赖硬编码的 tools，无法动态扩展
3. 外部系统连接配置分散，缺乏统一管理
4. 意图识别直接依赖 LLM 从全量 tools 中选择，效率低

需要设计一个架构，使 Skills 能够指导 Agent 执行，并支持外部系统集成。

## 决策

采用 **Skill Bridge 架构**，包含以下核心组件：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Skill Bridge 架构                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐        │
│  │ Intent Router   │ ──> │ Skill Registry  │ ──> │ Bridge Config   │        │
│  │ (意图预判)       │     │ (内容注入)       │     │ (连接配置)       │        │
│  └────────┬────────┘     └────────┬────────┘     └────────┬────────┘        │
│           │                       │                       │                  │
│           ▼                       ▼                       ▼                  │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │                    SkillAwareAgentHandler                            │    │
│  │  统一的 Agent 基类，支持 Skill 注入和 Bridge 调用                      │    │
│  └─────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 核心组件

| 组件 | 职责 |
|------|------|
| **Intent Router** | 根据关键词预判用户意图，缩小 tool 候选范围 |
| **Skill Registry** | 加载 Skill 内容，提取指导信息注入 LLM 上下文 |
| **Bridge Config** | 管理外部系统连接配置，安全存储认证信息 |
| **Bridge Adapter** | 将 tool call 转化为实际 API 调用 |
| **SkillAwareAgentHandler** | 统一的 Agent 基类 |

### 关键设计决策

1. **敏感信息存储**: 使用项目现有加密机制（复用）
2. **Intent Router 阈值**: 0.7（平衡精确率和召回率）
3. **MVP 范围**: 仅支持 ArgoCD，后续扩展 Flux CD
4. **Agent 迁移**: 所有 7 个内置 Agent 统一继承新基类

## 理由

1. **解耦知识与能力**: Skill 提供指导，Tool 提供能力，职责清晰
2. **可扩展性**: 新的外部系统只需添加 Bridge Adapter
3. **性能优化**: Intent Router 减少 tool 加载量 50%+
4. **一致性**: 统一的 Agent 架构降低维护成本
5. **安全性**: 敏感信息统一加密管理

## 影响

### 优点

- Skills 真正参与 Agent 执行流程
- 外部系统集成变得标准化
- Agent 开发模式统一
- 意图识别效率提升

### 缺点

- 需要迁移现有 7 个 Agent
- 增加了系统复杂度
- 需要额外的 Bridge 配置管理
