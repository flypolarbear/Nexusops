# ADR-001: Agent 执行环境

## 状态
已接受 (2024-02-16)

## 背景

Agent 需要一个安全的执行环境来处理用户请求，执行外部 API 调用，并与其他 Agent 协作。执行环境的选择直接影响：
- 安全性：Agent 是否能访问敏感数据
- 可靠性：Agent 的隔离和资源限制
- 可扩展性：能否水平扩展
- 运维复杂度：部署和监控的难度

## 选项

### 选项 A: 服务端执行（推荐）
- 在 NexusOps 后端服务器上执行
- 使用 Docker 容器进行隔离
- 所有 Agent 共享同一基础设施

**优点**：
- 可访问内网资源（K8s 集群、内部 API）
- 安全可控，便于审计
- 统一的日志和监控
- 便于实现凭证管理

**缺点**：
- 服务端资源消耗
- 单点故障风险（可通过集群解决）

### 选项 B: 客户端执行
- Agent 在用户浏览器中执行

**优点**：
- 减轻服务端压力
- 天然隔离

**缺点**：
- 安全风险（代码可被篡改）
- 无法访问内网资源
- 凭证管理困难

### 选项 C: 混合模式
- 部分在服务端，部分在客户端

**优点**：
- 灵活

**缺点**：
- 复杂度高
- 难以维护

## 决策

**采用选项 A：服务端执行 + Docker 容器隔离**

### 资源限制

```yaml
agent_container:
  # CPU 限制
  cpu_limit: "500m"          # 0.5 核心
  cpu_request: "100m"        # 最小保证 0.1 核心

  # 内存限制
  memory_limit: "512Mi"      # 最大 512MB
  memory_request: "128Mi"    # 最小保证 128MB

  # 执行超时
  execution_timeout: "30s"   # 单次执行最长 30 秒

  # 并发限制
  max_concurrent: 10         # 单个 Agent 最大并发数

  # 网络限制
  network:
    allow_external: true     # 允许访问外部 API
    allowed_hosts:
      - "*.cloudflare.com"
      - "*.kubernetes.default.svc"
      - "*.argocd.example.com"
```

### 隔离策略

```yaml
isolation:
  # 使用 Docker 容器隔离
  type: "docker_container"

  # 安全配置
  security:
    run_as_non_root: true
    read_only_root_filesystem: true
    no_new_privileges: true
    capabilities:
      drop: ["ALL"]

  # 文件系统
  filesystem:
    type: "tmpfs"
    size_limit: "64Mi"

  # 网络
  network:
    mode: "bridge"
    dns_servers:
      - "8.8.8.8"
      - "1.1.1.1"
```

## 后果

### 正面
- 安全可控的执行环境
- 可访问内部资源
- 便于审计和监控
- 统一的运维体验

### 负面
- 需要维护 Docker 基础设施
- 服务端资源消耗增加
- 需要实现容器池管理

### 风险
- 容器逃逸风险（通过安全配置缓解）
- 资源耗尽风险（通过资源限制缓解）

2. **Phase 4**: 实现完整的资源限制和隔离
