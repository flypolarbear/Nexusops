# ADR-001: Agent Gateway 采用 FastAPI 单体内核 + 可插拔执行层（阶段化演进）

## 状态
Accepted

## 日期
2026-02-24

## 背景
NexusOps 当前后端以 FastAPI 为主。产品在首期没有硬上线时间约束，但要求尽快形成稳定的 Agent 通用接入逻辑，并兼容现有 Jenkins/ArgoCD 等系统。

如果直接拆分独立网关服务，会增加部署、治理和联调复杂度；如果完全耦合在单体中，后续生态扩展会受限。

## 选项
1. 继续 FastAPI 单体扩展（强耦合）
2. 立即拆分独立 Gateway 服务
3. FastAPI 单体内核 + 可插拔执行层（推荐）

## 决策
采用选项 3：
1. Gateway 控制面（路由、鉴权、限流、审计、统一错误）先落在现有 FastAPI 内。
2. Agent 执行面采用可插拔 Adapter/Executor 模型，内置与第三方均通过同一契约接入。
3. 预留独立部署边界：当调用规模、租户隔离或组织边界触发阈值后，将 Gateway 控制面拆分为独立服务。

## 理由
1. 最快形成可交付能力，降低初期研发成本与沟通成本。
2. 避免“先微服务后产品”的过度设计，匹配当前阶段目标（稳定性与兼容优先）。
3. 通过可插拔执行层提前消除后续重构成本，保留中长期演进空间。

## 影响
1. 开发：短期开发效率更高，模块边界需严格定义（`gateway core` vs `agent executors`）。
2. 测试：需要重点覆盖契约一致性与插件兼容性。
3. 运维：先沿用现有发布链路，后续拆分时可按模块平滑迁移。

## 实施约束
1. 不在业务 Handler 中直接写第三方调用逻辑，必须通过 Executor 接口。
2. 所有 Agent 调用必须经过统一中间件链（鉴权、配额、日志、错误映射）。
3. 为未来拆分保留明确模块目录与内部 API 边界。
